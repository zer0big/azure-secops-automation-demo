## 개요

본 솔루션은 Azure Logic Apps를 사용하여 Azure API Management (APIM) 서비스의 보안 운영 모니터링을 자동화하고, Azure DevOps에 자동으로 인시던트를 생성합니다.

### 주요 기능
- ✅ **자동 오류 감지**: APIM Gateway 로그 24시간 모니터링
- ✅ **멀티 채널 알림**: Teams, 이메일, DevOps 작업 항목
- ✅ **관리 ID 인증**: 비밀 없는 보안 모델
- ✅ **일일 예약 실행**: 매일 오전 7시 (KST) 실행
- ✅ **REST API 직접 통합**: 커넥터 제한사항 우회

### 아키텍처 원칙
1. **비밀 제로 설계**: 모든 인증은 관리 ID를 통해
2. **코드형 인프라**: ARM 템플릿 기반 배포
3. **복원력**: 조건부 로직을 통한 오류 처리
4. **관측성**: 포괄적인 로깅 및 모니터링
5. **규정 준수**: 역할 기반 액세스 제어 (RBAC)

## 시스템 구성요소

### 1. Azure Logic App
**리소스 이름**: `logicapp-apim-aoai-monitoring`  
**목적**: 모니터링 워크플로우 오케스트레이션 엔진

**주요 기능**:
- 예약된 트리거 (Recurrence)
- API 호출을 위한 HTTP 액션
- 조건부 분기
- 멀티 채널 알림

**ID**:
- 시스템 할당 관리 ID
- Audience: `499b84ac-1321-427f-aa17-267ca6975798` (Azure DevOps)
- Audience: `https://api.loganalytics.io` (Log Analytics)

### 2. Log Analytics 작업 영역
**목적**: 중앙 집중식 로깅 및 쿼리 플랫폼

**쿼리 기능**:
```kusto
ApiManagementGatewayLogs
| where TimeGenerated > ago(24h)
| extend KST = TimeGenerated + 9h
| where ResponseCode != 200
| project KST, TimeGenerated, CorrelationId, ApiId, OperationId, 
          ResponseCode, BackendResponseCode, CallerIpAddress, Method, Url, LastErrorMessage
| order by TimeGenerated desc
| take 50
```

**수집 데이터**:
- APIM Gateway 로그
- 응답 코드 (200이 아닌 것 중심)
- 오류 메시지
- 추적을 위한 상관 관계 ID

### 3. Azure DevOps
**목적**: 인시던트 관리 및 추적

**작업 항목 생성**:
- **유형**: Issue
- **API 버전**: 7.0
- **인증**: 관리 ID
- **형식**: JSON Patch (application/json-patch+json)

**채워지는 필드**:
- System.Title
- System.Description (HTML 형식)
- System.AssignedTo
- Microsoft.VSTS.Common.Priority
- Microsoft.VSTS.Common.Severity

### 4. Microsoft Teams
**목적**: 실시간 협업 알림

**통합**:
- 채널 기반 게시
- 적응형 카드 형식 (HTML)
- 그룹 ID 및 채널 ID 필요

### 5. 이메일 (Office 365)
**목적**: 이메일 알림 전송

**구성**:
- Office 365 커넥터를 통한 SMTP
- HTML 본문 지원
- 높은 중요도 플래그 설정

## 데이터 흐름

### 1. 트리거 단계
```
시간: 매일 오전 07:00 (KST)
├─ Recurrence 트리거 실행
└─ 워크플로우 실행 시작
```

### 2. 쿼리 단계
```
액션: Query_APIM_Logs
├─ HTTP POST → https://api.loganalytics.io/v1/workspaces/{workspaceId}/query
├─ 인증: 관리 ID (audience: https://api.loganalytics.io)
├─ Body: 24시간 오류 로그에 대한 KQL 쿼리
└─ 응답: 오류 레코드가 포함된 JSON 테이블
```

### 3. 평가 단계
```
액션: Condition_Check_Errors
├─ 표현식: length(body('Query_APIM_Logs')?.tables?[0]?.rows) > 0
├─ TRUE 경로: 모든 알림 액션 실행
└─ FALSE 경로: 워크플로우 완료 (오류 없음)
```

### 4. 알림 단계 (오류 감지 시)
```
병렬 실행:
├─ Teams 알림
│  ├─ Teams API로 POST
│  └─ 오류 개수가 포함된 채널 메시지
│
├─ 이메일 알림
│  ├─ Office 365 API로 POST
│  └─ 오류 세부 정보가 포함된 HTML 이메일
│
└─ DevOps 작업 항목 (HTTP)
   ├─ POST → https://dev.azure.com/{org}/{project}/_apis/wit/workitems/$Issue
   ├─ 인증: 관리 ID (audience: 499b84ac-1321-427f...)
   ├─ Body: JSON Patch 작업
   └─ 풍부한 HTML 설명이 포함된 Issue 생성
```

## 보안 아키텍처

### 인증 모델

#### 1. 관리 ID (주요)
```
Logic App 시스템 할당 ID
├─ Azure DevOps API
│  └─ Audience: 499b84ac-1321-427f-aa17-267ca6975798
│
└─ Log Analytics API
   └─ Audience: https://api.loganalytics.io
```

**장점**:
- ✅ 관리할 비밀 없음
- ✅ 자동 자격 증명 순환
- ✅ Azure AD 통합
- ✅ Azure AD 로그를 통한 감사 가능

#### 2. API 연결 (커넥터)
- Teams: OAuth 기반 사용자 위임
- Outlook: OAuth 기반 사용자 위임
- DevOps (레거시): OAuth 기반, HTTP 방식으로 대체 권장

### 권한 부여 모델

**필요한 권한**:
```
Log Analytics 작업 영역
├─ Logic App ID

Azure DevOps 프로젝트
├─ Logic App ID
└─ 역할: Contributor 또는 Work Item Writer

Teams 채널
├─ 사용자 계정 (커넥터)
└─ 권한: 메시지 게시

Outlook
├─ 사용자 계정 (커넥터)
└─ 권한: 메일 전송
```

### 네트워크 보안
- 모든 트래픽은 HTTPS/TLS 1.2+ 사용
- Azure 백본 네트워크 (인터넷 노출 없음)
- 프라이빗 엔드포인트 (선택사항, 보안 강화용)

## 통합 지점

### 1. Log Analytics API
**엔드포인트**: `https://api.loganalytics.io/v1/workspaces/{workspaceId}/query`  
**메서드**: POST  
**인증**: 관리 ID  
**Content-Type**: application/json

**요청 본문**:
```json
{
  "query": "ApiManagementGatewayLogs | where TimeGenerated > ago(24h) ..."
}
```

**응답 형식**:
```json
{
  "tables": [
    {
      "name": "PrimaryResult",
      "columns": [...],
      "rows": [
        ["2026-01-03T16:00:00Z", "404", "GET", "/api/test", ...]
      ]
    }
  ]
}
```

### 2. Azure DevOps REST API
**엔드포인트**: `https://dev.azure.com/{org}/{project}/_apis/wit/workitems/$Issue`  
**API 버전**: 7.0  
**메서드**: POST  
**인증**: 관리 ID  
**Content-Type**: application/json-patch+json

**요청 본문 (JSON Patch)**:
```json
[
  {
    "op": "add",
    "path": "/fields/System.Title",
    "value": "APIM 오류 - 404 감지됨"
  },
  {
    "op": "add",
    "path": "/fields/System.Description",
    "value": "<h2>오류 세부정보</h2>..."
  }
]
```

### 3. Teams Webhook API
**채널 게시**: Beta API  
**인증**: 커넥터 OAuth  
**형식**: HTML 메시지 본문

### 4. Office 365 Mail API
**메일 전송**: v2 API  
**인증**: 커넥터 OAuth  
**형식**: HTML 이메일 본문

## 확장성 및 성능

### 현재 구성
- **실행 빈도**: 일일 (낮은 부하)
- **쿼리 범위**: 24시간
- **결과 제한**: 상위 50개 오류
- **타임아웃**: 기본 Logic App 타임아웃 (PT1H)

### 성능 지표
- **평균 실행 시간**: 5-15초
- **쿼리 지연 시간**: 2-5초
- **알림 지연 시간**: 각각 1-3초

### 확장 고려사항

#### 수평 확장
- Logic App: 실행당 자동 확장
- 상태 관리 불필요
- 무상태 워크플로우 설계

#### 수직 확장 옵션
1. **쿼리 범위 증가**: `ago(24h)`를 `ago(7d)`로 변경
2. **더 빈번한 실행**: 시간별로 변경 (요약 보고서에는 권장하지 않음)
3. **병렬 지역 배포**: 다중 지역 APIM 모니터링

### 비용 최적화
- 일일 실행으로 액션 비용 최소화
- 여러 알림을 위한 단일 워크플로우
- 관리 ID (Key Vault 비용 없음)
- 쿼리 결과 제한 (상위 50개)
